# aiguibin-platform-arch 架构管理平台 - 架构设计

## 1. 架构概述

### 1.1 架构风格
**微内核 + 插件式架构**
- 核心平台提供基础能力（用户、权限、菜单、配置）
- 各功能模块作为插件注册到平台
- 支持模块热插拔

### 1.2 技术选型

| 层级 | 技术组件 | 版本 |
|-----|---------|------|
| 后端框架 | Spring Boot | 3.2.5 |
| JDK | Java | 17 |
| 安全框架 | Spring Security + JWT | 6.x |
| 多数据源 | dynamic-datasource-spring-boot-starter | 4.3.0 |
| ORM | MyBatis-Plus | 3.5.6 |
| Excel处理 | EasyExcel | 3.3.4 |
| 定时任务 | Spring Scheduler + Quartz | - |
| 前端框架 | Vue | 3.4.21 |
| 构建工具 | Vite | 5.2.0 |
| UI组件 | Element Plus | 2.6.3 |
| SVN客户端 | SVNKit | 1.10.11 |
| 缓存 | Caffeine | 3.1.8 |

### 3.4 权限检查流程

```
1. 请求进入
   ↓
2. JWT Token验证
   ├─ 验证Token有效性
   ├─ 解析用户信息
   └─ 检查Token过期
   ↓
3. CSRF Token验证（写操作）
   ├─ 验证CSRF Token
   └─ 防止跨站请求伪造
   ↓
4. 权限检查
   ├─ 获取请求所需权限
   ├─ 获取用户拥有权限
   └─ 判断是否允许访问
   ↓
5. 数据权限过滤
   ├─ 根据用户数据范围
   └─ 过滤查询结果
   ↓
6. 执行请求
```

### 5.2 数据源分组管理
```java
/**
 * 数据源分组配置
 */
@Data
@ConfigurationProperties(prefix = "platform.datasource-group")
public class DatasourceGroupConfig {
    
    private Map<String, List<DbConfig>> groups = new HashMap<>();
    
    @Data
    public static class DbConfig {
        private String key;           // 数据源标识
        private String name;          // 数据源名称
        private String databaseName;  // 数据库名
    }
}

/**
 * 数据源分组服务
 */
@Service
public class DatasourceGroupService {
    
    @Autowired
    private DatasourceGroupConfig config;
    
    /**
     * 获取环境对应的所有数据源
     */
    public List<String> getDataSourcesByEnv(String env) {
        return config.getGroups().getOrDefault(env.toLowerCase(), Collections.emptyList())
            .stream()
            .map(DbConfig::getKey)
            .collect(Collectors.toList());
    }
    
    /**
     * 获取数据源对应的数据库名
     */
    public String getDatabaseName(String dataSourceKey) {
        return config.getGroups().values().stream()
            .flatMap(List::stream)
            .filter(c -> c.getKey().equals(dataSourceKey))
            .findFirst()
            .map(DbConfig::getDatabaseName)
            .orElse(null);
    }
}
```

## 6. 执行流程设计

### 6.1 单环境多数据库比对流程
```
1. 接收执行请求（手动/定时）
   ↓
2. SVN更新设计文档
   ↓
3. 解析Excel文档（目录、字段、索引）
   ↓
4. 获取该环境所有数据源配置
   ↓
5. 循环执行各数据库比对
   ├─ 5.1 切换数据源
   ├─ 5.2 执行表比对
   ├─ 5.3 执行字段比对
   ├─ 5.4 执行索引比对
   ├─ 5.5 执行贯标检查（条件触发）
   ├─ 5.6 生成该数据库结果Excel
   ├─ 5.7 SVN上传结果
   └─ 5.8 发送飞秋通知
   ↓
6. 记录执行日志
```

### 6.2 全环境比对流程
```
1. 接收全环境比对请求
   ↓
2. SVN更新设计文档
   ↓
3. 顺序执行各环境比对
   ├─ 3.1 DEV环境（7个数据库依次执行）
   ├─ 3.2 SIT环境（7个数据库依次执行）
   └─ 3.3 UAT环境（12个数据库依次执行）
   ↓
4. 汇总执行结果
   ↓
5. 发送汇总通知
```

### 6.3 登录认证流程
```
1. 用户提交用户名密码
   ↓
2. 验证账号密码
   ├─ 密码错误 → 记录错误次数
   ├─ 错误5次 → 锁定账号
   └─ 密码正确 → 继续
   ↓
3. 检查账号状态
   ├─ 已锁定 → 返回锁定信息
   └─ 正常 → 继续
   ↓
4. 查询用户所属机构列表
   ↓
5. 返回临时Token + 机构列表
   ↓
6. 用户选择机构
   ↓
7. 验证机构权限
   ├─ 无权限 → 返回错误
   └─ 有权限 → 继续
   ↓
8. 生成Access Token + CSRF Token
   ↓
9. 登录成功
```
