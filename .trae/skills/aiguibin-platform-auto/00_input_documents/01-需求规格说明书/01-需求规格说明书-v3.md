# aiguibin-platform-arch 架构管理平台 - 需求规格说明书

## 1. 项目概述

### 1.1 项目名称
**aiguibin-platform-arch** - 架构管理平台

### 1.2 项目定位
企业级架构管理平台，提供从数据库设计、接口管理、配置管理到开发规范的全生命周期架构管理能力。

## 3. 认证授权需求

### 3.1 登录流程

#### 3.1.1 两步登录
```
第一步：账号密码验证
├─ 输入用户名、密码
├─ 验证账号密码正确性
├─ 检查账号是否锁定
├─ 获取用户所属机构列表
└─ 返回Token和机构列表

第二步：机构选择
├─ 选择登录机构
├─ 验证用户机构权限
├─ 生成最终访问Token
├─ 生成CSRF Token
└─ 登录成功，跳转首页
```

### 3.2 安全机制

#### 3.2.1 Token机制
| Token类型 | 用途 | 有效期 |
|----------|------|--------|
| Access Token | 访问凭证 | 30分钟 |
| Refresh Token | 刷新凭证 | 7天 |
| CSRF Token | 防跨站请求 | 会话级 |

#### 3.2.2 账号锁定策略
| 触发条件 | 处理 |
|---------|------|
| 连续5次密码错误 | 自动锁定账号 |
| 手动锁定 | 管理员手动锁定 |
| 解锁方式 | 管理员解锁或定时解锁 |

#### 3.2.3 密码策略
- 最小长度8位
- 必须包含字母和数字
- 密码加密存储（BCrypt）

## 4. 数据库比对模块需求

### 4.1 功能概述
数据库比对是架构管理平台的核心功能之一，用于保障数据库设计文档与实际数据库结构的一致性。

### 4.2 数据源配置模型

#### 4.2.1 环境-数据库矩阵
| 环境 | 数据库数量 | 数据库列表 |
|-----|-----------|-----------|
| DEV | 7个 | ncms_credit, ncms_rule_base, ncms_collateral, ncms_customer, ncms_product, ncms_account, ncms_batch |
| SIT | 7个 | ncms_credit, ncms_rule_base, ncms_collateral, ncms_customer, ncms_product, ncms_account, ncms_batch |
| UAT | 12个 | ncms_credit, ncms_rule_base, ncms_collateral, ncms_customer, ncms_product, ncms_account, ncms_batch, ncms_report, ncms_history, ncms_archive, ncms_log, ncms_config |

#### 4.2.2 数据源配置结构
```yaml
# 多环境多数据库配置
datasource:
  dev:
    - key: dev-ncms-credit
      name: DEV-信贷库
      url: jdbc:mysql://dev-mysql:3306/ncms_credit
    - key: dev-ncms-rule
      name: DEV-规则库
      url: jdbc:mysql://dev-mysql:3306/ncms_rule_base
    # ... 共7个
  sit:
    - key: sit-ncms-credit
      name: SIT-信贷库
      url: jdbc:mysql://sit-mysql:3306/ncms_credit
    # ... 共7个
  uat:
    - key: uat-ncms-credit
      name: UAT-信贷库
      url: jdbc:mysql://uat-mysql:3306/ncms_credit
    # ... 共12个
```

### 4.3 比对执行模式

#### 4.3.1 单环境多数据库比对
- 选择一个环境（DEV/SIT/UAT）
- 该环境下的所有数据库依次执行比对
- 每个数据库独立生成结果文件

#### 4.3.2 全环境比对
- 顺序执行：DEV → SIT → UAT
- 每个环境下的所有数据库依次比对
- 支持并行执行（配置开关）
