# 湖北农信新信贷数据库分区分析 V2（精细化版） Spec

## Why
V1版本（db-partition-analysis）分析结果过于激进：1860张表中标记了1145张（61.6%）需要分区，且大量使用TENANT_ID作为分区键（存在法人行数据倾斜问题）。需要基于生产实际数据量、信贷业务语义和更严格的门槛，进行精细化重分析。

## What Changes（相比V1的改进）
- **BREAKING**: 分区门槛从"表名关键词匹配"改为"生产数据量+3-5年预估 > 1000万"
- **BREAKING**: 分区键选择禁用TENANT_ID（法人行倾斜），改用业务主键（CUST_NO/CTRT_NO/BUS_NO等）
- **BREAKING**: 分区数计算从经验估算改为精确公式：分区数 = 预估总量 / 300万（单分区 ≤ 300万）
- 新增：结合信贷知识逐表分析业务角色，而非仅靠表名关键词匹配
- 新增：以`老信贷生产环境迁移表数据量.xlsx`为数据量基准

## Impact
- 受影响文件：`DD-湖北农信基础配置检核\湖北农信数据库分区表清单.xlsx`（重新生成）
- 参考文件：
  - `AA-数据量\老信贷生产环境迁移表数据量.xlsx`（生产数据量基准）
  - `EE-湖北农信新信贷数据库设计文档\*.xlsx`（表结构）
  - `CC-新信贷基础知识\*.txt`（信贷业务语义）
  - `DD-湖北农信基础配置检核\partition_analysis_data.json`（已有表结构数据）

## 核心分析流程

```
每张表 → 查表结构 → 分析信贷业务角色 → 查生产数据量 → 预估3-5年增长
  → 超过1000万？
    ├─ 否 → 不分区（G列=否）
    └─ 是 → 选择分区键（避开TENANT_ID）→ 计算分区数（总量/300万）→ 填写完整信息
```

## ADDED Requirements

### Requirement 1: 生产数据量基准
系统 SHALL 读取`老信贷生产环境迁移表数据量.xlsx`，建立"表名→当前数据量"的基准映射。对于老系统中存在的表，直接使用其数据量；对于老系统中不存在的表（新系统新增），根据业务角色和相似表推测。

#### Scenario: 老系统有数据的表
- **WHEN** 表在`老信贷生产环境迁移表数据量.xlsx`中存在
- **THEN** 以老系统数据量为基准，估算新系统3-5年数据量 = 当前量 × 增长系数

#### Scenario: 新系统新增表
- **WHEN** 表在`老信贷生产环境迁移表数据量.xlsx`中不存在
- **THEN** 结合信贷业务语义和相似表的数据量模式，给出保守估算（标注为"预估"）

### Requirement 2: 分区判断门槛（1000万）
系统 SHALL 仅当一张表的"预估3-5年数据量 > 1000万"时，才标记为需要分区（G列=是）。

#### Scenario: 数据量超过1000万
- **WHEN** 预估3-5年数据量 > 10,000,000
- **THEN** G列标记为"是"，补充完整分区信息

#### Scenario: 数据量不足1000万
- **WHEN** 预估3-5年数据量 ≤ 10,000,000
- **THEN** G列标记为"否"

### Requirement 3: 分区键选择规则（避开TENANT_ID）
系统 SHALL 不推荐TENANT_ID作为分区键（因法人行数据倾斜）。分区键选择优先级如下：

| 表类型（业务语义） | 推荐分区键 | 原因 |
|---|---|---|
| 合同/借据类 | CTRT_NO / BUS_NO / IOU_NO | 合同/借据唯一编号，天然均匀分布 |
| 客户信息类 | CUST_NO / CUST_INTL_SEQ_NO | 客户编号，均匀分布 |
| 贷后检查/任务类 | TSK_NO / CHK_TASK_NO | 任务编号 |
| 申请/审批/批复类 | APLY_NO / BUS_NO | 申请/业务流水号 |
| 日志/审计类 | CREATE_TIME | 时间分区，3个月一个分区 |
| 档案/文件类 | ARS_NO / DOC_NO | 档案编号 |
| 营销活动类 | MKT_TSK_NO / DOC_NO | 营销任务编号 |
| 征信查询类 | BUS_NO / QUERY_NO | 查询流水号 |
| 额度类 | LMT_NO / CRLMT_NO | 额度编号 |

#### Scenario: 表中有业务主键
- **WHEN** 表中存在上述推荐分区键字段
- **THEN** 优先使用业务主键作为分区键

#### Scenario: 表中无合适业务主键
- **WHEN** 表中不存在任何推荐的分区键字段
- **THEN** 分析所有可用字段，选择基数最高、分布最均匀的非TENANT_ID字段；若实在找不到，标记H列为"待确认"

### Requirement 4: 分区数计算（单分区 ≤ 300万）
系统 SHALL 按以下公式计算初始分区数：

分区数 = CEILING(预估3-5年数据量 / 3,000,000)

- 分区数最小为1
- 分区数最大不超过50（避免过多分区带来管理负担）
- 日志类按时分区的表，初始分区数填0（表示按时间自动创建）

#### Scenario: 正常计算分区数
- **WHEN** 预估3-5年数据量 = 20,000,000
- **THEN** 分区数 = CEILING(20,000,000 / 3,000,000) = 7

### Requirement 5: 信贷业务语义分析
系统 SHALL 结合信贷基础知识，分析每张表在信贷系统中的业务角色，用于：
1. 帮助确定是否需要分区（辅助判断数据增长模式）
2. 帮助选择正确的分区键
3. 帮助估算新系统新增表的数据量

分析方法（逐表）：
1. 读取表的所有字段名和字段类型
2. 理解表的核心业务用途（客户管理？合同管理？贷后监控？）
3. 判断数据增长模式（随客户增长？随业务量增长？随时间线性增长？）
4. 预估3-5年数据量

### Requirement 6: 人工标注表（G列="是"）的强制保留
系统 SHALL 保留现有分区清单中G列="是"的93张表的分区标记，但需重新评估其分区键和分区数。如果人工选择的分区键是TENANT_ID，需在备注中说明风险。

### Requirement 7: 增长系数规则
对于生产环境已有数据的表，按以下增长系数估算3-5年数据量：

| 表类型 | 年增长率 | 3-5年增长系数 |
|---|---|---|
| 客户信息类 | 5-10% | 1.15-1.35 |
| 合同/借据类 | 10-20% | 1.35-1.75 |
| 日志/审计类 | 50-100% | 3.0-5.0 |
| 贷后检查/任务类 | 20-30% | 1.75-2.0 |
| 营销活动类 | 15-25% | 1.5-1.8 |
| 配置/字典类 | < 5% | 1.05-1.10 |
| 征信查询类 | 30-50% | 2.0-2.75 |
