5.1 审批决策框架
================================================================================

一、审批决策的五大维度

  贷不贷 → 贷多少 → 怎么贷 → 怎么保 → 怎么管

  这五大维度构成审批决策的完整框架，缺一不可。

二、决策矩阵

  新一代信贷系统将审批决策构建为一个多维度决策矩阵：

  ┌──────────┬───────────────────┬─────────────┐
  │ 决策维度  │ 考量因素           │ 否决条件     │
  ├──────────┼───────────────────┼─────────────┤
  │ 贷不贷    │ 资质、信用、用途   │ 黑名单、     │
  │           │                    │ 禁止行业     │
  ├──────────┼───────────────────┼─────────────┤
  │ 贷多少    │ 偿债能力、资本约束 │ 超限额、     │
  │           │                    │ 超偿付能力   │
  ├──────────┼───────────────────┼─────────────┤
  │ 怎么贷    │ 期限匹配、产品适配 │ 期限错配、   │
  │           │                    │ 用途不符     │
  ├──────────┼───────────────────┼─────────────┤
  │ 怎么保    │ 担保充足率、覆盖面  │ 担保不足、   │
  │           │                    │ 押品不合规   │
  ├──────────┼───────────────────┼─────────────┤
  │ 怎么管    │ 贷后条件、约束条款  │ 管理条件     │
  │           │                    │ 无法落实     │
  └──────────┴───────────────────┴─────────────┘

三、审批决策的信息输入

  审批决策需要综合以下信息：

  1. 客户基本信息（来自ECIF）
    - 身份信息、股权结构、关联关系

  2. 评级结果（来自评级系统）
    - 信用等级、PD值

  3. 授信情况（来自统一授信系统）
    - 现有授信总额度及使用情况
    - 本次业务是否超授信额度

  4. 尽调报告（来自尽调模块）
    - 经营分析、财务分析、用途和还款来源分析

  5. 外部数据（来自数据平台）
    - 征信报告、工商信息、司法信息、税务信息、舆情

  6. 限额约束（来自限额管理系统）
    - 行业限额、区域限额、产品限额

  7. 监管红线（来自合规引擎）
    - 大额暴露限制、关联交易、集中度管理

5.2 额度测算模型详解
================================================================================

一、对公客户额度测算

  1.1 营运资金缺口法（监管标准）

    适用于流动资金贷款的额度测算：

    步骤一：计算营运资金量

      营运资金量 = 上年度销售收入 × (1 - 上年度销售利润率)
                   × (1 + 预计销售收入年增长率)
                   / 营运资金周转次数
    
    步骤二：计算新增流动资金贷款额度

      新增额度 = 营运资金量 - 借款人自有资金
                  - 现有流动资金贷款 - 其他渠道提供的营运资金

    步骤三：计算最终额度

      额度上限 = min(新增额度, 净资产 × 倍数, 行业限额)

  1.2 固定资产项目额度测算

    适用于固定资产贷款：

    贷款额度 ≤ 项目总投资 - 项目资本金 - 其他资金来源
    
    其中：
    - 项目总投资 = 固定资产投资 + 铺底流动资金
    - 项目资本金 ≥ 项目总投资 × 最低资本金比例（20%-30%，因行业而异）
    - 贷款期限 ≤ 折旧年限，且 ≤ 政策规定最长年限

  1.3 基于偿债能力的额度测算（DSCR法）

    可用于还贷的现金流 = 净利润 + 折旧 + 摊销 - 营运资金增量 - 分红
                        ± 其他非现金项目

    DSCR = 可用于还贷的现金流 / 当年还本付息额
    
    要求 DSCR ≥ 1.1-1.3（不同银行、不同行业有差别）

    倒推最大贷款额度：
    最大年还本付息额 = 可用于还贷的现金流 / 最低DSCR
    → 最大贷款本金 = PV(利率, 期限, 最大年还本付息额)

二、零售客户额度测算

  2.1 住房贷款额度

    贷款额度 = 房屋评估价值 × (1 - 首付比例)
    
    首付比例因城施策：
    - 首套房：15%-20%
    - 二套房：25%-30%
    - 三套及以上：通常不予贷款

    同时满足还款能力约束：
    月还款额 ≤ 月收入 × DTI上限（通常50%，即负债/收入比 ≤ 50%）

  2.2 信用卡额度

    初始额度测算：
    
    基础额度 = f(月收入) × 收入倍数
              通常月收入的2-5倍，新客户从低端开始
    
    调整因子：
    - 信用评分加分/扣分
    - 人行征信记录：良好 +20%、有逾期 -50%/-100%
    - 本行存量客户贡献度加分

    动态额度调整：
    - 按时还款、额度使用率适中 → 提额
    - 经常最低还款、额度用满、多头借贷 → 降额/冻结

  2.3 消费贷款额度

    额度上限 = min(
      产品规定的单笔上限（如：综合消费贷上限100万）,
      月收入 × 还款倍数 × 还款月数（如：月收入×10%×120 = 月收入×12）,
      抵押物评估价值 × 抵押率上限（如：房产×70%）
    )

三、供应链金融额度测算

  3.1 应收账款融资额度
    融资金额 ≤ 应收账款金额 × 融资比例（通常 60-80%）
    融资比例取决于：
    - 买方信用等级（买方评级越高，比例越高）
    - 应收账款账龄（越短越好，超过180天通常不接受）
    - 历史退货率/争议率

  3.2 预付款融资额度
    单笔融资 ≤ 采购订单金额 × 融资比例（通常 50-70%）
    总额度控制：年度采购计划 × 一定比例

  3.3 存货融资额度
    融资金额 ≤ 存货价值 × 质押率（通常 50-70%）
    质押率取决于：
    - 商品品类（标准化程度高的大宗商品质押率高）
    - 价格波动性（波动越大，质押率越低）
    - 变现难易程度

5.3 利率定价引擎
================================================================================

一、定价的目标与约束

  目标：在风险、客户关系、市场竞争和监管约束之间找到最优利率。

  下限约束：利率 ≥ 资金成本 + 运营成本 + 风险成本（即不低于盈亏平衡点）
  上限约束：利率 ≤ 客户承受能力 且 ≤ 市场可比利率
  监管约束：利率不得违反最高利率限制（民间借贷利率上限的银行低报适用）

二、利率定价模型架构

  2.1 基础定价模型

    贷款利率 = FTP基准利率 + 运营成本率 + 风险溢价 + 目标利差

    a) FTP基准利率（内部资金转移定价）
      - FTP是银行内部虚拟的"资金价格"
      - 贷款端FTP = 市场资金成本 + 期限流动性溢价
      - 不同期限对应不同FTP曲线

    b) 运营成本率
      - 分摊的客户营销成本、审批成本、贷后管理成本
      - 零售贷款：通常 1.0%-2.0%
      - 对公贷款：通常 0.3%-0.8%

    c) 风险溢价
      风险溢价 = PD × LGD（即预期损失率）
      
      例如：某BBB级客户，PD=1.5%，LGD=45%
      风险溢价 = 1.5% × 45% = 0.675% = 67.5bp

    d) 目标利差
      - 满足银行ROE目标所需的利差
      - 综合考虑经济资本占用（RAROC门槛）

  2.2 综合定价模型

    最终利率 = 基础利率 + 调整因子

    调整因子包括：

    a) 客户关系定价调整
      客户综合贡献度（存款、结算、中间业务收入等）越高 → 利率优惠越大
      例如：
      - 存款贡献率 > 10%：利率下调20bp
      - 存款贡献率 > 20%：利率下调40bp

    b) 市场竞争调整
      参考同区域、同行业银行贷款利率
      竞争对手利率 - 10~30bp（保持竞争力但不打价格战）

    c) 贷款特征调整
      - 期限溢价：期限越长，加点越高（通常：每增加1年加5-15bp）
      - 担保折扣：强担保（房产抵押）可减点，信用贷款加点
      - 金额折扣：大额贷款可适当减点

三、定价审批权限

  利率定价需要分级授权：

  ┌─────────────────────────────────────────────┐
  │ 利率水平              │ 审批层级              │
  ├─────────────────────────────────────────────┤
  │ ≥ 基础利率 + 50bp    │ 客户经理自主           │
  │ ≥ 基础利率 + 0bp     │ 支行行长审批           │
  │ ≥ FTP基准利率 + 成本  │ 分行审批               │
  │ < FTP基准利率 + 成本  │ 总行审批（需说明理由）  │
  └─────────────────────────────────────────────┘

四、RAROC在定价中的应用

  一笔贷款的RAROC计算：

  RAROC = (贷款利息收入 - FTP资金成本 - 运营成本 - 预期损失) / 经济资本

  准入条件：RAROC ≥ RAROC门槛（例如12%）

  如RAROC不达标，可：
  - 提高贷款利率
  - 增强担保（降低LGD → 降低经济资本）
  - 缩短期限（降低经济资本）
  - 增加交叉销售（提升综合贡献度）

5.4 规则引擎与自动审批
================================================================================

一、规则引擎的定位

  在新一代信贷系统中，规则引擎是实现"自动审批"和"审批辅助"的核心模块。

  两类规则：
  - 硬规则（Hard Rule）：必须满足，不满足则直接拒绝或阻断
  - 软规则（Soft Rule）：建议性规则，不满足时预警提示，仍需人工决策

二、典型规则分类

  2.1 准入规则
  
    示例：
    - 客户年龄 ≥ 18 岁 且 ≤ 65 岁（零售）
    - 企业成立年限 ≥ 2 年
    - 行业分类不在"禁止准入行业清单"中
    - 反洗钱筛查通过
    - 非失信被执行人

  2.2 额度规则

    示例：
    - 单一客户总授信 ≤ 净资本的 10%（一般）/ 15%（集团）
    - 住房贷款 LTV ≤ 70%（首套）/ 60%（二套）
    - 信用卡月还款额 ≤ 月收入 × 50%

  2.3 评级规则

    示例：
    - 对公客户信用等级 ≥ BBB（投资级底线）
    - 零售客户信用评分 ≥ 600

  2.4 担保规则

    示例：
    - 信用贷款需评级 ≥ A 且期限 ≤ 1年
    - 房产抵押率 ≤ 70%
    - 保证人评级 ≥ A

  2.5 合规规则

    示例：
    - 不得为"两高一剩"行业新增授信（除非属于绿色升级）
    - 房地产贷款集中度不超过监管上限
    - 地方政府融资平台贷款压降要求

  2.6 集中度规则

    示例：
    - 单一行业集中度 ≤ 信贷总额的 20%
    - 单一区域集中度 ≤ 信贷总额的 15%
    - 大额风险暴露（贷款金额 > 净资本5%）需逐笔报告

三、自动审批决策流程

  新一代系统自动审批流程：

  申请提交 → 身份认证 → 反欺诈筛查 → 黑名单筛查
    → 规则引擎执行（全部硬规则检查）→ 评分卡/模型打分
    → 额度测算 → 利率定价 → 自动生成审批结论

  自动审批适用条件：
  - 标准化产品（如信用卡、消费贷款、小额经营贷）
  - 金额在自动审批权限内（如 ≤ 50万元）
  - 所有硬规则均通过
  - 人工复核随机抽检（如 5%）

  人工审批介入条件：
  - 超过自动审批金额阈值
  - 硬规则通过但多个软规则触发预警
  - 评分处于灰色地带（边界分数）
  - 复杂产品（并购贷款、银团贷款、项目融资）

四、规则引擎技术实现

  新一代信贷系统通常采用：
  - Drools / EasyRules 等开源规则引擎，或自研规则引擎
  - 规则配置可视化（业务人员可配置规则，无需IT介入）
  - 规则版本管理 + 灰度发布
  - 规则执行效率监测（响应时间 < 100ms）
  - A/B测试能力（新旧规则对比）

5.5 AI辅助决策体系
================================================================================

一、AI在信贷决策中的应用场景

  1.1 智能尽调
    - NLP自动解析财务报表，提取关键指标
    - OCR识别合同、发票、权证等文档
    - 关联关系知识图谱自动构建
    - 财务异常智能检测（如：毛利率异常波动）

  1.2 智能评级
    - 机器学习模型替代/补充传统逻辑回归评分卡
    - 非结构化数据处理：新闻舆情情感分析 → 定性评价评分
    - 动态评级：现金流、交易行为实时打分

  1.3 智能审批决策
    - 复杂案件的智能审批建议
    - 历史审批案例相似度匹配（找到最相似的历史案例及其结果）
    - 审批知识库（FAQ、政策解读、案例库）

  1.4 智能定价
    - 客户价格敏感度预测
    - 动态最优定价（平衡利润与成交率）
    - 竞争对手利率实时监测与对标

  1.5 智能贷后预警
    （详见第六章）

二、AI模型的治理

  在新一代银行信贷系统中，AI模型需要严格治理：

  2.1 可解释性要求
    - 监管要求：自动化决策需向客户解释原因
    - 信贷审批拒绝原因必须可追溯、可解释
    - 因此倾向使用：逻辑回归、决策树、规则集等可解释模型
    - 深度学习等"黑箱"模型需配套SHAP/LIME等解释工具

  2.2 公平性
    - 模型不得包含歧视性变量（种族、性别、宗教等）
    - 公平性测试：不同群体间的审批率差异分析
    - 监管合规：不得违反《个人信息保护法》

  2.3 稳定性
    - PSI（Population Stability Index）监控
    - 模型衰减预警与触发重训机制
    - 模型备份与回滚能力

  2.4 审批闭环
    - 模型仅是辅助工具，最终决策权在审批人
    - 模型建议与人工决策不一致时，记录原因
    - 定期分析模型准确率与人工判断偏差

5.6 审批质量评价
================================================================================

一、审批效率指标

  - 平均审批时效（从提交到出审批结论）
  - 自动审批率（自动审批笔数 / 总审批笔数）
  - 审批通过率（通过笔数 / 总审批笔数）
  - 审批一次通过率（不需补件修改的比例）

二、审批质量指标

  - 新增不良率 = 审批通过后 12个月/24个月内变为不良的金额 / 审批总额
  - 审批拒绝客户后悔率 = 被拒绝客户在其他银行正常还款的比例
  - 审批人不良率排名
  - 审批推翻率（审批结论被上级否决的比例）

三、审批合规指标

  - 超权限审批事件数
  - 审批条件落实率（放款前条件是否全部落实）
  - 监管检查问题数
