# 审批服务控制器(ApprovalController)技术分析文档

## 1. 控制器概述

`ApprovalController` 是审批服务的RESTful API入口，负责处理所有与审批流程相关的HTTP请求。该控制器提供了从提交审批、审批操作到查询审批任务等完整的审批生命周期管理功能。

**路径前缀**: `/api/approval`
**核心依赖**: `ApprovalService` 接口及其实现类 `ApprovalServiceImpl`

## 2. 方法详细分析

### 2.1 提交审批 - `submitForApproval`

**API路径**: `POST /submit/{recordId}`

#### 输入参数
| 参数名 | 类型 | 来源 | 描述 |
|--------|------|------|------|
| recordId | Long | Path | 变更记录ID |
| operator | String | Request Attribute | 操作人信息，格式：`userNum|userName` |
| X-Page-Path | String | Header | 页面路径 |
| X-Button-Name | String | Header | 按钮名称 |
| request | HttpServletRequest | Request | HTTP请求对象 |

#### 返回值
```java
ApiResponse<Long> // 包含提交结果，返回变更记录ID
```

#### 完整工作流程

```
┌───────────────────────────────────────────────────────────────────────────┐
│ 1. 解析请求参数                                                           │
│    - 获取operator信息                                                     │
│    - URL解码页面路径和按钮名称                                           │
│    - 解析IP地址                                                          │
├───────────────────────────────────────────────────────────────────────────┤
│ 2. 调用 ApprovalService.submitApproval()                                 │
│    - 参数：recordId, operator, pagePath, buttonName, ip                  │
├───────────────────────────────────────────────────────────────────────────┤
│ 3. Service层处理流程 (ApprovalServiceImpl.submitApproval)                │
│    ┌───────────────────────────────────────────────────────────────────┐ │
│    │ 3.1 参数验证：检查recordId是否为空                                 │ │
│    ├───────────────────────────────────────────────────────────────────┤ │
│    │ 3.2 解析operator参数，验证格式是否为"userNum|userName"              │ │
│    ├───────────────────────────────────────────────────────────────────┤ │
│    │ 3.3 查询变更记录：通过changeRecordMapper.selectById(recordId)       │ │
│    ├───────────────────────────────────────────────────────────────────┤ │
│    │ 3.4 状态验证：检查变更记录当前状态是否为"待审批"                     │ │
│    ├───────────────────────────────────────────────────────────────────┤ │
│    │ 3.5 权限验证：检查操作人是否为创建人                               │ │
│    ├───────────────────────────────────────────────────────────────────┤ │
│    │ 3.6 查询默认审批流程：通过approvalFlowMapper查询活跃的默认流程       │ │
│    ├───────────────────────────────────────────────────────────────────┤ │
│    │ 3.7 生成流程实例编码                                               │ │
│    ├───────────────────────────────────────────────────────────────────┤ │
│    │ 3.8 获取第一个审批节点：通过approvalNodeMapper查询流程的第一个节点   │ │
│    ├───────────────────────────────────────────────────────────────────┤ │
│    │ 3.9 保存更新前的变更记录副本（用于历史记录）                       │ │
│    ├───────────────────────────────────────────────────────────────────┤ │
│    │ 3.10 更新变更记录：                                               │ │
│    │       - 设置flowId为默认流程ID                                     │ │
│    │       - 设置currentNodeId为第一个节点ID                             │ │
│    │       - 设置current_status为不同的状态                              │ │
│    │       - 设置approvalInstanceId为新生成的流程实例编码                  │ │
│    │       - 设置approvalStatus为"PENDING"                               │ │
│    │       - 设置submitTime为当前时间                                    │ │
│    │       - 调用changeRecordMapper.updateById(record)更新记录            │ │
│    ├───────────────────────────────────────────────────────────────────┤ │
│    │ 3.11 创建待办任务：为第一个节点的审批人生成记录                     │ │

│    │       - 设置flowId、nodeId、businessType等信息                      │ │
│    │       - 设置taskStatus为"PENDING"                                   │ │

```

## 4. 数据流程总览

### 4.1 审批流程启动
1. **API调用**: 客户端调用 `POST /api/approval/submit/{recordId}`
2. **参数解析**: 解析请求参数，获取变更记录ID、操作人信息等
3. **服务调用**: 调用 `ApprovalService.submitApproval()`
4. **业务逻辑**: 
   - 验证参数和权限
   - 查询默认审批流程和第一个节点
   - 更新变更记录状态
   - 创建待办任务
   - 保存历史记录和操作日志
5. **数据库操作**: 
   - 更新 `biz_change_record` 表
   - 插入 `biz_approval_task` 表
   - 插入 `biz_change_history` 表
   - 插入 `sys_operation_log` 表
   - 插入 `biz_approval_log` 表
6. **返回结果**: 返回ApiResponse<Long>，包含变更记录ID

### 4.2 审批操作
1. **API调用**: 客户端调用 `POST /api/approval/task/{taskId}/approve` 或 `POST /api/approval/task/{taskId}/reject`
2. **参数解析**: 解析请求参数，获取任务ID、审批意见、操作人信息等
3. **服务调用**: 调用 `ApprovalService.approve()` 或 `ApprovalService.reject()`
4. **业务逻辑**: 
   - 验证参数和权限
   - 查询任务和相关记录
   - 更新任务状态
   - 更新变更记录状态
   - 处理流程流转（同意时）
   - 保存历史记录和操作日志
5. **数据库操作**: 
   - 更新 `biz_approval_task` 表
   - 更新 `biz_change_record` 表
   - 插入新的 `biz_approval_task` 表记录（如果有下一节点）
   - 插入 `biz_approval_log` 表
   - 插入 `sys_operation_log` 表
6. **返回结果**: 返回ApiResponse<Boolean>，表示操作结果

### 4.3 审批查询
1. **API调用**: 客户端调用 `GET /api/approval/tasks/todo`、`GET /api/approval/tasks/processed` 等查询接口
2. **参数解析**: 解析查询参数，获取审批人信息、分页参数等
3. **服务调用**: 调用对应的查询方法，如 `ApprovalService.queryTodoTasks()`
4. **业务逻辑**: 
   - 构建查询条件
   - 执行数据库查询
   - 分页处理结果
5. **数据库操作**: 
   - 查询 `biz_approval_task` 表或 `biz_approval_log` 表
6. **返回结果**: 返回ApiResponse<Page<T>>，包含查询结果和分页信息

## 5. 关键业务规则与约束

### 5.1 权限控制
- 提交审批：只有变更记录的创建人可以提交审批
- 审批操作：只有任务指定的审批人可以进行审批操作
- 特殊用户：用户"aiguibin"具有超级权限，可以跳过审批人权限验证

### 5.2 状态流转规则
- 变更记录状态：
  - 待审批 → 审批中-节点1 → 审批中-节点2 → ... → 已审批
  - 待审批 → 审批中-节点1 → 已拒绝
- 任务状态：
  - PENDING（待办）→ 已完成
  - PENDING（待办）→ REJECTED（拒绝）

### 5.3 日志记录
- 所有关键操作都记录操作日志（sys_operation_log）
- 所有审批流转都记录审批日志（biz_approval_log）
- 变更记录的所有状态变化都记录变更历史（biz_change_history）

## 6. 性能与安全考量

### 6.1 性能优化
- 使用MyBatis Plus的BaseMapper接口，简化数据库操作
- 合理使用索引（如审批任务表的approver_num、task_status、assign_time等字段）
- 分页查询，避免一次性返回大量数据

### 6.2 安全措施
- 参数验证：所有API接口都进行参数验证
- 权限验证：关键操作都进行权限检查
- SQL注入防护：使用MyBatis Plus的安全查询机制
- 日志脱敏：敏感信息在日志中进行脱敏处理

## 7. 总结

`ApprovalController` 是审批服务的核心控制器，提供了完整的审批生命周期管理功能。通过与 `ApprovalService` 及其实现类的协作，实现了从提交审批、审批操作到查询审批任务等一系列功能。

该控制器遵循了RESTful API设计原则，使用统一的返回格式 `ApiResponse<T>`，便于前端处理。同时，通过分层设计（Controller → Service → Mapper），实现了业务逻辑与数据访问的分离，提高了代码的可维护性和可扩展性。

整个审批系统的设计考虑了业务规则、权限控制、状态流转、日志记录等多方面因素，确保了审批流程的安全性、可靠性和可追溯性。
