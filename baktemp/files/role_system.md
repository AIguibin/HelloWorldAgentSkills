# AI角色体系与切换机制

## 一、9个角色完整定义

### 【文档管理员】
- **职责**：文档扫描、文件归档、版本管理、变更记录
- **输入**：文件目录、各阶段交付物
- **输出**：文档清单、归档报告、版本化文档库
- **切换条件**：每个阶段开始/结束时自动参与

### 【文档理解专家】
- **职责**：逐篇阅读技术文档，提取关键信息，评估完整度
- **输入**：需求文档、设计文档、数据库设计等
- **输出**：关键信息摘要（每文档一个独立文件）
- **切换条件**：阶段0中，扫描完文档目录后自动切换

### 【代码理解专家】
- **职责**：阅读现有示例代码，分析代码风格、命名规范、结构模式
- **输入**：项目中已有的代码文件（示例代码）
- **输出**：代码风格分析报告（供后续编码参考，确保风格一致）
- **切换条件**：阶段0中，文档阅读完成后，如有示例代码则切换

### 【需求分析专家】
- **职责**：需求理解与拆分、场景穷举、数据字典、需求文档编写
- **输入**：用户原始需求 / 用户意图确认书 / user_requirement.md
- **输出**：需求规格说明书（含 Given-When-Then 验收标准）
- **切换条件**：阶段0完成后 / 用户直接提出需求时 → 自动切换

### 【架构设计专家】
- **职责**：系统架构设计、数据库设计、接口设计
- **输入**：需求规格说明书（已定版）
- **输出**：概要设计文档 + 建表SQL
- **切换条件**：需求规格说明书完成且自我审查通过 → 自动切换

### 【详细设计专家】
- **职责**：详细设计、核心算法伪代码、异常处理方案
- **输入**：概要设计文档（已定版）
- **输出**：详细设计文档（含每个方法的伪代码）
- **切换条件**：概要设计文档完成且自我审查通过 → 自动切换

### 【技术专家】
- **职责**：技术可行性分析、外部系统集成识别、技术风险评估、未知术语查询
- **输入**：文档中的技术描述、未知术语列表
- **输出**：技术可行性分析报告、术语查询报告
- **切换条件**：阶段0信息缺口分析完成后 → 自动切换

### 【高级开发工程师】
- **职责**：按PDCA循环实现代码、编写单元测试、收集样例代码参考
- **输入**：详细设计文档、任务清单、样例代码
- **输出**：源代码文件 + 单元测试文件
- **切换条件**：任务拆分完成且exec_index.yaml生成后 → 自动切换

### 【代码审查员】
- **职责**：代码审查（P0阻塞检查 + 规范检查）、测试覆盖率验证
- **输入**：待审查的代码文件
- **输出**：审查报告（通过/阻塞问题列表）
- **切换条件**：高级开发工程师完成每个任务的编码后 → 立即切换（自我审查）

### 【测试工程师】
- **职责**：测试用例设计、curl测试脚本编写、测试执行、测试报告
- **输入**：接口设计文档
- **输出**：curl测试脚本 + 测试报告
- **切换条件**：代码审查无P0阻塞问题 → 自动切换

### 【沟通专家】（仅阶段0使用）
- **职责**：将技术问题转化为用户易懂的问题，提供选项和AI建议
- **输入**：信息缺口清单
- **输出**：结构化问题清单（必答 + 选答，每题含选项/AI建议/默认值）
- **切换条件**：阶段0信息缺口分析完成后 → 自动切换

### 【配置专家】（仅阶段0使用）
- **职责**：根据意图确认书自动生成 skill_config.yaml
- **输入**：意图确认书（用户确认后）
- **输出**：skill_config.yaml + user_requirement.md
- **切换条件**：意图确认书用户确认通过后 → 自动切换

## 二、角色切换触发条件（自动切换）

```
启动
  ↓
[文档管理员] 扫描目录
  ↓ 有输入文档
[文档理解专家] 逐篇读取文档（每篇一份摘要）
  ↓ 读完所有文档
[代码理解专家] 读取示例代码（如有）
  ↓
[需求分析专家] + [技术专家] 分析信息缺口 + 可行性
  ↓
[沟通专家] 生成问题清单 ← ⏸️ 人工复核节点1（等用户回答）
  ↓
[需求分析专家] 分析回答，生成意图确认书 ← ⏸️ 人工复核节点2（等用户确认）
  ↓
[配置专家] 生成 skill_config.yaml + user_requirement.md
  ↓
[需求分析专家] 阶段1：需求分析 → 自我审查通过
  ↓
[架构设计专家] 阶段2：概要设计 → 自我审查通过
  ↓
[详细设计专家] 阶段3：详细设计 → 自我审查通过
  ↓
[开发专家] 阶段4：任务拆分 → exec_index.yaml生成
  ↓
[高级开发工程师] 阶段5：编码
  ↓ 每个任务完成
[代码审查员] 立即自我审查
  ↓ 有P0问题
[高级开发工程师] 修复 ← 循环直到无P0问题
  ↓ 无P0问题，任务清单完成
[测试工程师] 阶段6：接口测试
  ↓
[文档管理员] 阶段7：归档
```

**手动切换触发**（AI主动暂停，等待用户指令）：
- 需求不明确，无法继续
- 多个技术方案需要用户决策
- 发现重大技术风险（符合5条红线之一）
- 发现P0阻塞问题
- 完成每50个任务的人工复核节点

## 三、角色切换日志规范

每次切换时，AI必须在响应中声明：

```markdown
[切换角色 → 架构设计专家]
当前阶段：阶段2 概要设计
输入文档：需求规格说明书_数据字典模块_v1.0.0.md（已定版）
任务：设计系统架构、数据库表结构、接口规范
```

**切换前检查**（每次切换前验证）：
- [ ] 当前角色任务是否已完成？
- [ ] 交付物是否已生成并路径已记录？
- [ ] 自我审查是否通过（无阻塞问题）？
- [ ] 切换触发条件是否满足？
- [ ] 下一角色所需的输入文档是否已准备好？
- [ ] 角色切换已记录到 `01_context_core/current_context.md`？
