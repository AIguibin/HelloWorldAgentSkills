# 编码审查清单（扩展版）

## 通用检查项（所有语言）

### 代码质量
- [ ] 命名是否清晰、符合规范（无拼音、无单字母变量）
- [ ] 方法长度是否合理（建议不超过50行）
- [ ] 是否有重复代码（抽取为公共方法）
- [ ] 魔法数字是否已替换为常量或枚举
- [ ] 注释是否有意义（解释"为什么"而非"是什么"）

### 异常处理
- [ ] 所有异常是否被正确捕获处理
- [ ] 无空 catch 块（至少记录日志）
- [ ] 异常信息是否有意义（包含上下文信息）
- [ ] 资源是否在 finally 块或 try-with-resources 中关闭
- [ ] 是否正确区分了受检异常和运行时异常

### 安全
- [ ] 用户输入是否经过校验（长度、格式、范围）
- [ ] SQL 是否使用参数化查询（防注入）
- [ ] 敏感信息是否未出现在日志中（密码、Token等）
- [ ] 接口是否有权限控制

### 性能
- [ ] 循环内是否有数据库查询（N+1问题）
- [ ] 大数据量操作是否有分页
- [ ] 是否有不必要的重复计算
- [ ] 字符串拼接是否使用 StringBuilder（Java）

---

## Java / Spring Boot 专项

### 代码规范（阿里巴巴Java开发规范）
- [ ] 类名使用 UpperCamelCase
- [ ] 方法名、变量名使用 lowerCamelCase
- [ ] 常量使用 UPPER_CASE_WITH_UNDERSCORE
- [ ] 包名全部小写

### Spring 相关
- [ ] @Transactional 是否只加在 Service 层
- [ ] @Autowired 是否替换为构造器注入（推荐）
- [ ] Controller 是否只做参数校验和调用 Service，无业务逻辑
- [ ] Service 是否只做业务逻辑，无直接操作数据库

### MyBatis-Plus 相关
- [ ] 实体类是否有 @TableName、@TableId 注解
- [ ] 逻辑删除字段是否有 @TableLogic 注解
- [ ] 批量插入是否使用 saveBatch（不要循环单条插入）
- [ ] 查询是否指定了必要的字段（避免 SELECT *）

### 单元测试
- [ ] 每个 Service 方法至少有一个测试用例
- [ ] 正常流程、异常流程、边界值都有测试
- [ ] Mock 对象是否正确配置（不要遗漏 when...thenReturn）
- [ ] 测试方法名是否描述了测试场景（方法名_场景_预期结果）

---

## 数据库设计审查

- [ ] 每张表都有主键（推荐 bigint 自增或 UUID）
- [ ] 每张表都有 create_time、update_time、is_deleted 字段
- [ ] 外键关联字段是否有索引
- [ ] 频繁查询的字段是否有索引
- [ ] 字段命名是否符合规范（下划线命名）
- [ ] 字段长度是否合理（varchar 不要无脑 255）
- [ ] 建表SQL是否有 ENGINE=InnoDB CHARSET=utf8mb4

---

## 接口设计审查

- [ ] 路径是否符合 RESTful 规范（名词复数，不含动词）
- [ ] HTTP 方法是否正确（GET 查询，POST 创建，PUT/PATCH 更新，DELETE 删除）
- [ ] 响应是否有统一格式 `{code, message, data}`
- [ ] 错误码是否有文档说明
- [ ] 入参是否有 @Valid 校验注解
- [ ] 分页接口是否返回总数

---

## P0级别问题（必须修复后才能提交）

以下问题发现后，立即停止执行，上报并等待修复：

1. **SQL注入风险**：使用了字符串拼接构造SQL
2. **未处理的空指针**：可能的NPE未做判断
3. **敏感信息泄露**：密码、Token等出现在响应或日志中
4. **事务不完整**：多个数据库操作未在同一事务中
5. **测试覆盖率严重不足**：核心方法无测试
