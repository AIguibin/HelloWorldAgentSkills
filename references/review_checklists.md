## 需求分析审查清单

### 完整性
- [ ] 文档结构完整（概述/业务流程/功能需求/数据字典/场景清单/非功能需求）
- [ ] 所有功能点已描述，无遗漏
- [ ] 每个用户故事都有 Given-When-Then 验收标准
- [ ] 数据字典定义了所有实体的所有字段
- [ ] 场景清单覆盖：正常场景、异常场景、边界场景、权限场景、状态场景

### 准确性
- [ ] 业务描述准确，无歧义
- [ ] 数据字典字段类型、长度、必填设置正确
- [ ] 验收标准可量化、可测试

### 一致性
- [ ] 术语使用统一（同一概念只有一个名称）
- [ ] 前后描述一致，无矛盾
- [ ] 数据字典与功能描述一致

### 可测试性
- [ ] 每个验收标准都有明确的输入、操作、预期结果
- [ ] 测试数据有具体示例，无"合法数据"等模糊描述

## 概要设计审查清单

### 架构设计
- [ ] 分层设计合理（Controller/Service/Mapper 职责清晰）
- [ ] 模块划分合理，职责单一
- [ ] 模块间依赖方向正确（高层依赖低层，不反向依赖）
- [ ] 技术选型符合项目约束

### 数据库设计
- [ ] 表结构与数据字典一致
- [ ] 每张表包含通用字段（id/create_time/update_time/is_deleted/create_by/update_by）
- [ ] 字段类型和长度合理（不无脑 varchar(255)）
- [ ] 主键设计合理（bigint自增 或 雪花ID）
- [ ] 外键关联字段已建索引
- [ ] 频繁查询字段已建索引
- [ ] 所有表和字段有注释
- [ ] 建表SQL可直接执行（无语法错误）

### 接口设计
- [ ] 路径符合 RESTful 规范（名词复数，无动词）
- [ ] HTTP方法使用正确（GET查/POST增/PUT改/DELETE删）
- [ ] 请求参数定义完整（类型/是否必填/校验规则/说明）
- [ ] 响应使用统一格式 `{code, message, data}`
- [ ] 错误码有完整定义
- [ ] 分页接口返回 total

## 代码审查清单（每个任务完成后必查）

### 🔴 P0 阻塞问题（发现即停止，等待修复）

- [ ] **无SQL注入风险**（使用参数化查询，不使用字符串拼接构造SQL）
- [ ] **无高风险NPE**（所有可能为null的对象在使用前已判断）
- [ ] **无敏感信息泄露**（密码/Token/私钥未出现在日志或响应中）
- [ ] **事务完整**（多步写操作在同一 @Transactional 方法内）
- [ ] **测试覆盖率达标**（行≥80%，分支≥70%，方法=100%）

### 🟡 代码规范（修复后继续）

**命名规范**
- [ ] 类名使用 UpperCamelCase
- [ ] 方法名/变量名使用 lowerCamelCase
- [ ] 常量使用 UPPER_CASE_WITH_UNDERSCORES
- [ ] 无无意义命名（a, b, temp, data...）
- [ ] 无拼音命名

**代码质量**
- [ ] 无魔法数字（使用常量或枚举）
- [ ] 无空 catch 块
- [ ] 无不必要的重复代码（DRY原则）
- [ ] 无在循环内执行数据库查询（N+1问题）
- [ ] 无未使用的import和变量

**注释规范**
- [ ] 所有 public 方法有 JavaDoc 注释（@param/@return/@throws）
- [ ] 复杂业务逻辑有行内注释
- [ ] 注释解释"为什么"，而非"是什么"

**日志规范**
- [ ] 使用 @Slf4j，不使用 System.out.println
- [ ] 关键操作有 INFO 级别日志
- [ ] 异常有 ERROR 级别日志（包含异常对象）
- [ ] 日志信息包含关键上下文（ID、操作类型等）

**Spring 规范**
- [ ] Controller 层不含业务逻辑
- [ ] Service 层涉及写操作已加 @Transactional
- [ ] @Autowired 使用构造器注入（或 @RequiredArgsConstructor）
- [ ] 接口请求对象有 @Valid 注解

**MyBatis-Plus 规范**
- [ ] 实体类有 @TableName 和 @TableId
- [ ] 逻辑删除字段有 @TableLogic
- [ ] 批量操作使用 saveBatch，不循环单条
- [ ] 查询指定字段，避免 SELECT *

- [ ] 每个 public 方法至少有1个测试用例
- [ ] 覆盖了正常场景（Happy Path）
- [ ] 覆盖了所有异常场景（每种业务异常都有测试）
