## 1. 项目概述

### 1.1 项目背景
aiguibin-platform-arch 是一个微内核 + 插件式架构的数据库管理平台，提供数据库比对、认证授权、系统设置等核心功能。

### 1.2 设计目标
- **高扩展性**：微内核架构，支持插件式扩展
- **安全性**：RBAC + 数据权限模型，JWT Token认证
- **易用性**：提供友好的Web界面和Knife4j接口文档
- **稳定性**：多数据源动态路由，本地缓存优化

### 3.2 分层架构

#### 3.2.1 前端层
- **技术栈**：Vue 3 + Vite + Element Plus
- **职责**：用户界面展示、交互处理、路由管理、状态管理
- **核心组件**：
  - 登录页面
  - 系统设置模块（用户、机构、部门、角色、菜单、日志）
  - 数据库比对模块（数据源配置、比对执行、执行记录）
  - 定时任务配置模块

#### 3.2.2 网关层（可选）
- **技术栈**：Nginx 或 Spring Cloud Gateway
- **职责**：请求路由、负载均衡、统一认证入口

#### 3.2.3 应用层
- **技术栈**：Spring Boot 3.2.5
- **职责**：Controller层，接收HTTP请求，参数校验，返回响应
- **核心Controller**：
  - AuthController：认证授权
  - UserController：用户管理
  - OrgController：机构管理
  - DeptController：部门管理
  - RoleController：角色管理
  - MenuController：菜单管理
  - DbCompareController：数据库比对
  - ScheduleController：定时任务

#### 3.2.4 服务层
- **技术栈**：Spring Service + MyBatis-Plus
- **职责**：业务逻辑处理，事务管理
- **核心Service**：
  - AuthService：认证服务
  - UserService：用户服务
  - OrgService：机构服务
  - RoleService：角色服务
  - ExcelService：Excel解析服务
  - DbCompareService：数据库比对服务
  - ScheduleService：定时任务服务

#### 3.2.5 数据访问层
- **技术栈**：MyBatis-Plus Mapper
- **职责**：数据库CRUD操作
- **核心Mapper**：
  - SysUserMapper
  - SysOrgMapper
  - SysRoleMapper
  - DbDatasourceConfigMapper
  - DbExecuteRecordMapper

#### 3.2.6 数据层
- **技术栈**：MySQL 8.0 + Druid连接池
- **职责**：数据持久化
- **核心数据库**：
  - platform_config：平台配置库（主库）
  - 业务数据库：DEV、SIT、UAT环境数据库

## 4. 微内核 + 插件式架构

### 4.1 架构设计理念
- **微内核**：核心平台提供基础能力（认证授权、数据访问、配置管理）
- **插件式**：各功能模块作为插件注册，可独立开发、部署、扩展

### 4.2 核心模块

#### 4.2.1 认证授权模块（核心）
- **职责**：用户认证、权限检查、Token管理
- **核心组件**：
  - JwtTokenProvider：JWT Token生成与验证
  - AuthenticationFilter：认证过滤器
  - PermissionInterceptor：权限拦截器
  - DataScopeAspect：数据权限切面

#### 4.2.2 系统设置模块（核心）
- **职责**：用户、机构、部门、角色、菜单、日志管理
- **核心功能**：
  - 用户CRUD、密码重置、锁定/解锁
  - 机构/部门树形结构管理
  - 角色权限配置
  - 菜单树形结构管理
  - 操作日志、登录日志查询

#### 4.2.3 数据库比对模块（插件）
- **职责**：Excel解析、数据库比对、结果生成
- **核心功能**：
  - Excel目录Sheet、字段Sheet、索引Sheet解析
  - 数据库表结构、字段、索引查询
  - 差异比对（新增、删除、修改）
  - 贯标检查
  - 结果Excel生成
  - SVN提交（可选）

#### 4.2.4 定时任务模块（插件）
- **职责**：定时任务配置、调度、执行记录
- **核心功能**：
  - Cron表达式配置
  - 任务启用/禁用
  - 执行记录查询
  - 手动触发

## 5. 认证授权架构

### 5.1 两步登录机制

```
Step 1: 账号密码验证
┌─────────┐     ┌─────────────────┐     ┌─────────────────┐
│  用户   │────▶│  AuthController │────▶│  AuthService    │
└─────────┘     └─────────────────┘     └────────┬────────┘
                                                  │
                                                  ▼
                                         ┌─────────────────┐
                                         │  验证用户名密码  │
                                         │  返回机构列表    │
                                         └─────────────────┘

Step 2: 选择机构
┌─────────┐     ┌─────────────────┐     ┌─────────────────┐
│  用户   │────▶│  AuthController │────▶│  AuthService    │
└─────────┘     └─────────────────┘     └────────┬────────┘
                                                  │
                                                  ▼
                                         ┌─────────────────┐
                                         │  生成JWT Token  │
                                         │  返回用户信息    │
                                         └─────────────────┘
```

### 5.2 JWT Token体系

| Token类型 | 有效期 | 用途 |
|-----------|--------|------|
| Access Token | 30分钟 | 接口访问认证 |
| Refresh Token | 7天 | 刷新Access Token |
| CSRF Token | 会话级 | 防止CSRF攻击 |

### 5.3 RBAC + 数据权限模型

```
用户 (User)
  ├── 关联多个角色 (Role)
  │     ├── 关联多个菜单 (Menu)
  │     │     ├── 菜单类型：目录/菜单/按钮
  │     │     └── 权限标识：user:add, user:edit
  │     └── 数据范围：全部/本机构/本部门/本人
  └── 关联多个机构 (Org)
        └── 树形结构：总部 → 分公司 → 部门
```

### 7.2 缓存配置

```java
@Configuration
@EnableCaching
public class CacheConfig {
    
    @Bean
    public CacheManager cacheManager() {
        CaffeineCacheManager cacheManager = new CaffeineCacheManager();
        cacheManager.setCaffeine(Caffeine.newBuilder()
                .initialCapacity(100)
                .maximumSize(1000)
                .expireAfterWrite(30, TimeUnit.MINUTES));
        return cacheManager;
    }
}
```

## 9. 关键技术决策

### 9.1 为什么选择微内核 + 插件式架构？
- **高扩展性**：新功能可以作为插件独立开发，不影响核心模块
- **低耦合**：核心模块与插件模块解耦，便于维护和测试
- **灵活部署**：可以根据需要选择加载哪些插件

### 9.2 为什么选择 MyBatis-Plus？
- **简化开发**：内置通用Mapper、Service，减少重复代码
- **代码生成**：支持代码生成器，快速生成Entity、Mapper、Service
- **分页插件**：内置分页插件，简单易用
- **性能优秀**：基于MyBatis，性能稳定

### 9.3 为什么选择 Caffeine 而不是 Redis？
- **本地缓存**：无需网络开销，性能更高
- **简单易用**：API简单，配置方便
- **替代方案**：根据用户需求，使用Caffeine替代Redis，降低部署复杂度

### 9.4 为什么选择 Knife4j？
- **基于Swagger**：兼容Swagger注解
- **界面美观**：提供更友好的UI界面
- **功能丰富**：支持在线调试、接口搜索等功能

## 12. 总结

本架构设计采用**微内核 + 插件式**架构，基于**Spring Boot 3.2.5**和**Vue 3.4.21**技术栈，实现了：

1. **认证授权**：两步登录、JWT Token、RBAC + 数据权限
2. **系统设置**：用户、机构、部门、角色、菜单、日志管理
3. **数据库比对**：Excel解析、多数据源比对、结果生成
4. **定时任务**：Cron配置、任务调度、执行记录

架构具有**高扩展性**、**安全性**、**易用性**和**稳定性**，满足项目需求。
